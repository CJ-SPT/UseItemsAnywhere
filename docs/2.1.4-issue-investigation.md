# 2.1.4 issue investigation

## Bot reload failures

The old startup code merged player access slots into the shared
`Inventory.FastAccessSlots` array in both `Awake` and `Start`. Player reload
prefixes also temporarily overwrote that array in place, filling unused entries
with Dogtag and restoring it in a finalizer.

In the installed EFT 40743 assembly, bot reloads read the same shared array.
`GetAcceptableItemsNonAlloc` calls `InventoryEquipment.GetSlot`, which indexes
the equipment's `_cachedSlots` directly. An extended slot that is outside that
particular equipment cache causes `IndexOutOfRangeException`; a missing slot can
also cause a null-reference failure.

The merge deduplicated entries, so calling it twice does **not** by itself grow
the array indefinitely. With the installed Pack 'n Strap, its three slots are
already a subset of this mod's five extended slots. Replacing rather than merging
is therefore not a sufficient general fix for the unsafe shared access pattern.
The reporter's exact failing slot and mod combination have not been reproduced.

### Changes

- Remove this mod's startup writes and temporary reload mutations of the shared
  array.
- Route player reload and ammo-selection queries directly through the configured
  reload slots, including magazines, loose ammunition, revolvers, barrel reloads,
  underbarrel launchers, and chamber-loading callbacks.
- Route the player grenade input query through the grenade slot settings.
- Keep bot queries on the native/shared slot selection, filtering entries against
  that bot's actual equipment cache before calling the native collector. Preserve
  valid slots contributed by another mod; never write its shared array.
- Preserve query predicates, item types, output buffers, and slot ordering.
  Skip invalid, missing, and duplicate slots.

Concrete callers are patched instead of generic method definitions, avoiding
Mono generic-method sharing ambiguity. All fourteen installed call sites are
checked by the regression harness; runtime patch setup rejects a missing or
unexpected query instead of silently leaving a reload path unpatched.

### Validation

From the repository root:

```powershell
dotnet run --project tests/InventorySlotQueries/InventorySlotQueries.Tests.csproj -c Release
dotnet build UseItemsAnywhere.sln -c Release -p:DeployOnBuild=false
```

The test executable substitutes inventory objects at the native boundary and
inspects the actual installed `Assembly-CSharp.dll` with Cecil. It verifies the
production query helpers and transpiler transformations, including stack
signatures, branch labels, and exception boundaries. It does not install Harmony
patches in a running Unity process.

Live checks remain necessary: ordinary and quick player reload, backpack/belt
magazines, loose rounds, shotgun/revolver/launcher reload, ammo selection, grenade
selection, and sustained AI combat without reload exceptions. Test with and
without Pack 'n Strap. Client/server restarts remain manual.

## Inventory items malfunction after being moved

**Unconfirmed. No reproduction or reporter error log is available.**

The installed server setting is named
`fixProfileBreakingInventoryItemIssues`, under `fixes` in `core.json`; the report
omits `Item` from its name. Here the setting is currently false and has not been
changed for this investigation.

The installed server invokes this cleanup from the game-start profile handling
path, not on each inventory move. It can remove identical duplicate item records,
replace conflicting duplicate IDs, and normalize other profile data. That makes
the setting useful context, but does not establish a Use Items Anywhere defect.
No profile or server repair behavior has been changed.

To investigate, record the exact item/template, starting and destination slots,
stash versus raid context, what “no longer functions” means, other inventory mods,
and the first client/server exception. Compare the same starting snapshot of a
disposable profile with cleanup off/on across separate startups, then repeat with
Use Items Anywhere disabled. Preserve server cleanup messages such as
`Deleted duplicate item` or `Replace duplicate item Id`, if present. Do not use
the production profile for experiments with cleanup settings.
